# Portfolio Studio

Vinay Ramathota's UI/UX portfolio website with a private admin dashboard.

- **Public site** (`/`): hero with a seated profile image, typed job titles, work, about, experience, skills, education, certifications and a contact form. Light, dark, match-device and browser-colour themes. Copy buttons for e-mail and phone. Resume download / open / preview.
- **Admin** (`/admin/`): multiple profiles (one live at a time), every section editable, duplicate cards as drafts, image editor, theme editor, contact inbox with Gmail replies, backup / restore, contact export, password recovery codes, activity log.

Stack: Node 22 + Express, PostgreSQL (Neon in production, PGlite locally), no front-end build step.

---

## Run it locally

```bash
npm ci
cp .env.example .env     # then edit the values
npm start                # http://localhost:3000  and  http://localhost:3000/admin/
```

Leave `DATABASE_URL` empty to use the built-in PGlite database in `.data/` (no install needed).

Tests:

```bash
npm test                              # 20 API tests on an in-memory database
python3 test/browser/e2e.py           # 28 browser checks (needs: pip install playwright && playwright install chromium; server running on :3000 with a fresh .data/)
```

## Deploy (GitHub → Render → Neon)

1. **Database.** At [neon.tech](https://neon.tech) create a free project and copy the connection string (`postgresql://…?sslmode=require`).
2. **Render.** In the Render dashboard choose **New → Blueprint**, pick this GitHub repo. Render reads `render.yaml` and asks for:
   | Variable | What to enter |
   |---|---|
   | `DATABASE_URL` | the Neon connection string |
   | `ADMIN_BOOTSTRAP_ID` | your admin ID |
   | `ADMIN_BOOTSTRAP_PASSWORD` | a temporary password (shown once on the login page until your first sign-in) |
   | `ADMIN_DEFAULT_CODE` | a long code that unlocks one sign-in with the default password |
   | `ADMIN_RECOVERY_CODE` | a different long code that opens the recovery request |

   `DATA_ENCRYPTION_KEY` and `SESSION_SECRET` are generated by Render. Copy `DATA_ENCRYPTION_KEY` somewhere safe.
3. **First sign-in.** Open `https://<your-service>.onrender.com/admin/` straight away. The default credentials are shown until the first successful sign-in, so sign in before sharing the link, then change the password under **Account & security**.

Every push to `main` redeploys. Content edits in the admin never need a redeploy.

**Free-plan limits.** The service sleeps after ~15 minutes idle; the first visit after that takes 30–60 seconds. Render's free plan also **blocks outgoing e-mail ports**, so Gmail sending (replies, notifications, reset links) needs the service on a paid instance (Starter). Contact-form messages are still saved to the inbox on the free plan.

## E-mail (Gmail App Password)

1. Turn on 2-Step Verification for the Google account.
2. Google Account → Security → App passwords → create one (16 letters).
3. Admin → **E-mail**: enter the Gmail address and App Password, save, then **Test connection**.

The App Password is encrypted (AES-256-GCM) with `DATA_ENCRYPTION_KEY` and stored server-side. It is never sent to the browser or included in backups.

## Sign-in, recovery and security

- **Hints** `role_context` / `role_context@length` always appear on the login page. They're hints, not credentials (change them with `ADMIN_HINT_ID` / `ADMIN_HINT_PASSWORD`).
- **Default password** keeps working until you change it; the dashboard shows a warning card until you do.
- **Forgot your password? → `#code`** prompt:
  - `ADMIN_DEFAULT_CODE` → one sign-in with the default password within 15 minutes, then a new password is required.
  - recovery code (`ADMIN_RECOVERY_CODE`, or one set in the admin) → **Queue recovery request**. If e-mail and a recovery e-mail are set up, a single-use reset link (30 min) goes to the recovery e-mail saved in the admin.
  - anything else → "That verification code isn't valid." The codes never appear in page text, tooltips or errors.
- **Operator reset** (always works): in Render → your service → **Shell**, run
  `npm run admin:reset -- <admin-id> <new-password>`. Content is untouched.
- Passwords are hashed with scrypt; sessions are HttpOnly, Secure, SameSite=Strict cookies; admin writes require a custom header and same origin; login, code and contact endpoints are rate-limited; uploads are checked by file signature (JPG/PNG/WebP/PDF only); CSV exports neutralise spreadsheet formulas; a strict Content-Security-Policy is set.

## Backups

Admin → **Backup & export**:
- **Download backup**: all profiles, content, theme and (optionally) uploaded images/PDFs as JSON. Never includes passwords, codes, sessions or the App Password.
- **Restore**: the file is validated first and shows what it contains; restoring needs typed confirmation. Admin accounts, e-mail settings and messages are not changed.
- **Export contacts**: all messages or e-mails only, as CSV or JSON.

Neon also keeps point-in-time history for the database.

## Versions

Each website update is saved as an isolated version and never overwritten:

```
versions/
  v1/
    prompt_v1.txt     the prompt that produced v1
    VERSION.md
    source/           full copy of the site at v1
```

To record a new version after making changes:

```bash
npm run version:snapshot -- 2 path/to/prompt_v2.txt
git add -A && git commit -m "v2" && git tag v2 && git push --follow-tags
```

The script refuses to overwrite an existing version folder. Git tags (`v1`, `v2`, …) mark the same points in history.

## Troubleshooting

| Problem | Fix |
|---|---|
| `Missing required environment variables` on start | Set `DATABASE_URL` and `DATA_ENCRYPTION_KEY` (32+ chars) in Render. |
| Login page says admin isn't set up | Set `ADMIN_BOOTSTRAP_ID` and `ADMIN_BOOTSTRAP_PASSWORD`, then redeploy. |
| "Couldn't reach Gmail's mail server" | Render free plan blocks mail ports. Move the service to a paid instance. |
| "Gmail rejected the sign-in" | Create a new App Password; 2-Step Verification must be on. |
| Saved Gmail App Password stopped working after changing `DATA_ENCRYPTION_KEY` | Re-enter the App Password in Admin → E-mail. |
| First visit is slow | Free plan cold start; wait up to a minute. |
